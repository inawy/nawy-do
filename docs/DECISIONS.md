# سجل القرارات — Nawy To Do

صيغة القرار: **السياق ← القرار ← البدائل المرفوضة ← الحالة**. لا يُعدَّل قديم؛ يُضاف قرار جديد يشير إليه.

## D-001 — مستودع مستقل بمكدّس حديث (2026-10-27) · مُعتمد

**السياق:** تطبيق `nawy.app` الحالي vanilla JS ويبقى كما هو. المنتجات الأخرى (Today، Notes، Focus) مبنية بـ React/TS/Vite/Dexie.
**القرار:** Nawy To Do مستودع جديد نظيف: Vite + React + TypeScript صارم + Dexie + Vitest (وPlaywright لاحقًا). لا كود منقول من التطبيق القديم.
**مرفوض:** تحويل `nawy.app` الحالي (يخالف قاعدة «تغييرات تدريجية لا إعادة كتابة» هناك).

## D-002 — لا تذكيرات وهو مغلق (2026-10-27) · مُعتمد

**القرار:** لا نعرض أي وعد بتذكير لا نستطيع الوفاء به. تذكيرات الـ PWA تعمل فقط وهو مفتوح أو حسب النظام؛ أي ميزة تذكير تُبنى لاحقًا بصياغة صادقة. (مأخوذ من قرار Nawy Today D-002.)

## D-003 — الاسم والعبارة (2026-10-27) · مُعتمد

**القرار:** «ناوي دو» / Nawy To Do، العبارة «ناوي تعمل إيه؟»، المهمة تُسمّى «نية». ناوي هو المظلة، ومعه Today وNotes وFocus. الرابط المخطط: `nawy.to/do`.

## D-004 — فصل الطبقات بقواعد lint (2026-10-27) · مُعتمد

`core ← data ← features ← ui ← app` بـ `no-restricted-imports`، مع اختبار `tests/layers.test.ts` كشبكة أمان.

## D-005 — الوقت يُمرَّر ولا يُقرأ (2026-10-27) · مُعتمد

`core` و`data` لا يستدعيان `new Date()` ولا `Date.now()` (قاعدة lint). التواريخ المدنية نصوص `YYYY-MM-DD` بلا منطقة زمنية. وعند الحاجة لحساب تواريخ يُبنى `core/time` بقرار جديد.

## D-006 — tombstones ودمج على مستوى السجل (2026-10-27) · مُعتمد

**القرار:** الحذف يستبدل السجل بـ tombstone بلا محتوى. الدمج: الأحدث `updatedAt` يفوز؛ عند التعادل يفوز tombstone؛ ثم ترتيب ثابت لا يعتمد على ترتيب المعاملات. `updatedAt` يزيد دائمًا بدقة (`nextUpdatedAt`).

## D-007 — لا lockfile بعد (2026-10-27) · مؤقت

**السياق:** المستودع أُنشئ من بيئة بلا وصول لـ npm registry، فلم يُولَّد `package-lock.json`.
**القرار:** CI يستخدم `npm install` مؤقتًا. **شرط المراجعة:** أول commit للـ lockfile، ثم التحويل إلى `npm ci`.

## D-008 — إصدار المخطط وصيغة الملف (2026-10-27) · مُعتمد

تغيير المخطط = `db.version(n)` جديد (لا تعديل لقديم) + اختبار ترحيل. ملف التصدير بصيغة `nawy-do` برقم إصدار؛ الأحدث يُرفض، والأقدم يُرقّى خطوة بخطوة، والاستيراد يتحقق قبل الكتابة ثم **يدمج** ولا يستبدل. حد لعدد السجلات. tombstones تُنظَّف فقط بعد 90 يومًا (`data/purge.ts`).
**مؤجل:** لقطات احتياطية قبل الترحيل — تُبنى مع أول إصدار v2.

## D-009 — النطاق (2026-10-27) · مُعتمد

**القرار:** `do.nawy.app` (نطاق فرعي أنشأه صاحب المشروع). ملف `public/CNAME` يحمل النطاق. يحتاج: سجل DNS من نوع CNAME إلى `inawy.github.io`، وتفعيل Pages (Source = GitHub Actions) وإدخال النطاق المخصص في إعدادات المستودع. `nawy.to/do` يُوجَّه لاحقًا إلى هذا النطاق من `nawy.to/public/links.json`.

## D-010 — سلوك القائمة الأول (2026-10-27) · مُعتمد

النية الجديدة تظهر في الأعلى. المنجزة في قسم مطوي «المنجزة (n)» أسفل القائمة. الحذف يكتب tombstone ويعرض «تراجع» 7 ثوانٍ؛ التراجع يعيد السجل بـ `updatedAt` أحدث من tombstone فيفوز في الدمج. ساعة النظام تُقرأ في `app/clock.ts` فقط.

## D-011 — تفاصيل النية والتواريخ (2026-10-27) · مُعتمد

**القرار:** لكل نية `notes` و`due` (تاريخ مدني `YYYY-MM-DD` بلا منطقة زمنية). التواريخ تُحسب بأعداد صحيحة في `core/model/civil.ts` بلا `Date` ولا `Intl`. «اليوم» يُمرَّر من `app/clock.ts` (منطقة الجهاز). التسميات: النهارده/بكرة/امبارح ثم «5 نوفمبر» بأرقام لاتينية (تنسيق عربي كامل مؤجل).
**قواعد التعديل:** عنوان فارغ أو تاريخ غير صالح يُتجاهل (تبقى القيمة القديمة)؛ مسح الملاحظات أو التاريخ يحذف الحقل. التحقق من التاريخ يرفض ما لا وجود له في التقويم (30 فبراير).
**عرض «مجدولة»:** النوايا المفتوحة التي لها تاريخ، مقسّمة: متأخرة / النهارده / قادمة، بترتيب التاريخ.
**لا تذكيرات** (D-002): التاريخ للعرض فقط.
