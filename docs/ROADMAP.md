# خارطة التطوير — Nawy To Do (جوال أولًا)

الهدف: تطبيق مهام بمستوى Google Tasks وMicrosoft To Do، **يعمل كأنه تطبيق أندرويد أصلي** (لمس وإيماءات وتثبيت ومشاركة)، ويصلح للويب والديسكتوب، بكود معياري يُصان ويتوسع. ثقيل الشغل يؤجَّل ولا يُرتجَل: كل مرحلة صغيرة، تُنشر، وتُراجَع قبل التي بعدها.

## 1. أين نحن (لقطات الإنتاج من CI)

اللقطات تُلتقط آليًا من النسخة المبنية بشاشة Pixel 7 وديسكتوب، وتُنشر على الفرع [`ci-screenshots`](https://github.com/inawy/nawy-do/tree/ci-screenshots) (`android-1-main.png`، `android-2-details.png`، … و`chromium-*`). كل مرحلة تُقارن بها.

ما تراه فيها اليوم، بصراحة:

| ملاحظة                                                                     | الأثر على الجوال                                               |
| -------------------------------------------------------------------------- | -------------------------------------------------------------- |
| زر «تحديد» بلا تنسيق (زر المتصفح الافتراضي) وشريط عنوان مزدحم بثلاثة أزرار | يبدو غير مكتمل؛ يحتاج قائمة «المزيد»                           |
| خانة الإضافة أعلى الشاشة                                                   | بعيدة عن الإبهام؛ التطبيقات الأصلية تضعها أسفلًا (FAB أو شريط) |
| حقل التاريخ بصيغة `mm/dd/yyyy` الإنجليزية                                  | يكسر العربية؛ يحتاج منتقي تواريخ مُحلّى                        |
| لا إيماءات (سحب جانبي للإنجاز والحذف، ضغط مطوّل للتحديد)                   | غياب أهم عادات الجوال                                          |
| الورقة السفلية لا تُسحب للإغلاق                                            | تعوّد المستخدم على سحبها                                       |
| ديسكتوب: عمود ضيق وفراغ كبير                                               | يحتاج تخطيطًا أوسع ولوحة تفاصيل جانبية                         |
| CSS كتابة يدوية واحدة لكل شاشة                                             | يصعب توسيعه باتساق                                             |

## 2. المبادئ المعمارية (لا تُكسر)

1. **الطبقات** `core ← data ← features ← ui ← app` بقواعد ESLint (D-004، D-015). لا تجاوز.
2. **منافذ ومحوّلات (Ports & Adapters)**: ما يخص مزوّدًا خارجيًا (Dexie، Drive، إشعارات، مشاركة) خلف **واجهة** في `core`، ومحوّل واحد في `data/adapters`. الواجهة لا تعرف إلا الخدمات. _هذا غير مكتمل اليوم: `features` تستورد `NawyDoDb` مباشرة (المرحلة A، تأكدت منه المراجعة المستقلة)._
3. **كل موديول بواجهة عامة `index.ts` فقط**، بلا استيراد عميق.
4. **القلب نقي**: بلا React ولا DOM ولا ساعة (D-005).
5. **لا ملف يتجاوز ~200 سطرًا ولا دالة تتجاوز مسؤولية واحدة**؛ المكوّن الكبير يُقسَّم، لا يُتجاهل. (قاعدة لينت للحجم تُضاف في المرحلة A.)
6. **اعتماد جديد = سطر سبب في `DECISIONS.md`** وإصدار مثبّت (سياسة nawy-architecture). نفضّل الـ Web Platform على المكتبة.
7. **لا حذف فعلي**: tombstones والدمج على مستوى السجل (D-006). أي مخطط جديد = نسخة Dexie جديدة + نسخة أمان.
8. **الجوال أولًا في التصميم والاختبار**: كل ميزة تُصمَّم لشاشة 360px ولمس، ثم تتسع.

## 4. المراحل

كل مرحلة: PR أو أكثر صغير، بوابتها الإلزامية (tsc + lint + format + vitest + build + e2e)، **لقطات قبل/بعد**، ومراجعة معمارية مستقلة (§5) قبل الدمج للمراحل المعمارية. **الترتيب أُعيد بعد المراجعة الأولى** ([`REVIEWS.md`](REVIEWS.md)).

### A0 — سلامة البيانات (قبل أي ميزة؛ صغيرة وعالية القيمة)

- تقييد `updatedAt` عند الاستيراد والاسترجاع بحد أقصى `الآن + يوم`، فلا يتجمد سجل في المستقبل. اختبار.
- الاستيراد في **معاملة واحدة** (قوائم + نوايا). اختبار فشل جزئي.
- نسخة الأمان تحفظ **كل** الجداول لا `tasks` فقط؛ معالجة `blocked`؛ إعادة تسمية `migrate.ts` إلى `snapshot.ts`.
- `navigator.storage.persist()` وعرض حالة التخزين (أندرويد قد يمسح بيانات موقع غير مثبّت)، وتنبيه المستخدم لتصدير نسخة.
- **قبول:** اختبارات جديدة للثلاثة؛ لا تغيير في الشكل.

### A — أساس معماري

- منفذا `TaskRepository` و`ListRepository` في `core/ports`؛ محوّل Dexie؛ محوّل ذاكرة للاختبار؛ `features` تعتمد الواجهة فقط؛ قاعدة لينت تمنع `NawyDoDb` في `features` (D-024).
- معرّفات (`newId`) تُحقن كالساعة؛ سياسة أخطاء واحدة للـ hooks؛ تراجع **مكدّس** (أكثر من عنصر) وليس عنصرًا واحدًا.
- `resolveSelection` و`canSort` و`optionsFor` تنتقل إلى `core` باختبارات؛ تقسيم `TasksScreen` (< 200 سطر)؛ قاعدة لينت لحجم الملف؛ منع الحذف الفعلي على كل `src`.
- `package-lock.json` و`npm ci` وDependabot وحد حجم الحزمة وحد تغطية (يحتاج منك رفع القفل).
- **قبول:** لا استيراد لـ Dexie خارج `data`؛ اختبارات hooks تعمل بمحوّل الذاكرة (دليل أن المنفذ حقيقي).

### C — شاشة الجوال (البنية أولًا)

- شريط إضافة سفلي (أو FAB)، **قائمة «المزيد»** (تحديد/بيانات/بحث)، ترويسة تتقلص، safe-area و`dvh`، أهداف لمس ≥ 48dp، `overscroll-behavior` لمنع تمرير-للتحديث العرَضي.
- منتقي تاريخ مُحلّى (اليوم/بكرة/الأسبوع القادم/تاريخ).
- **قبول:** لقطة Pixel 7 تُراجَع بصريًا؛ كل أداة بإبهام واحدة.

### B — نظام التصميم (Tailwind) **بعد بنية C**

- Tailwind v4: `tokens.css` ← `@theme`، و`ui/primitives`: `Button`، `IconButton`، `Field`، `Chip` (والورقة في D).
- ترحيل موديولًا بعد موديول؛ لا «كل شيء مرة واحدة»؛ لا ترحيل شاشة قبل استقرار بنيتها.
- **قبول:** لقطات مطابقة قبل/بعد؛ لا لون أو مسافة خارج الرموز.

### D — الإيماءات والورقة السفلية

- `Sheet` واحدة (سحب للإغلاق) **مع زر الرجوع في أندرويد** (`history` لكل ورقة) فلا يخرج الرجوع من التطبيق.
- سحب الصف: إنجاز / حذف مع تراجع (مكدّس)، **RTL**؛ ضغط مطوّل لبدء التحديد؛ اهتزاز خفيف. **لكل إيماءة بديل بلا إيماءة** (قائمة «المزيد»/ورقة التفاصيل) للوصولية.
- لا تعارض مع التمرير ولا مع dnd-kit (`touch-action` صريح).
- **قبول:** اختبارات Playwright بلمس حقيقي على مشروع `android`؛ و**جهاز حقيقي يجربه المالك** قبل إعلان الجاهزية (مجدول صراحة).

### E — تكامل أندرويد

- `manifest`: `shortcuts`، `share_target` (النص المستقبَل يُقيَّد طوله ويمر عبر التحقق، ومعالجته بلا إنترنت تُختبر)، `display_override`، لقطات تثبيت، `theme_color` للوضع الداكن؛ شاشة تثبيت داخلية.
- **قبول:** فحص manifest آلي؛ التثبيت الفعلي يتحقق منه المالك.

### F — ميزات المرتبة الأولى

- «يومي»، تكرار، وقت استحقاق، تذكيرات (أثناء فتح التطبيق؛ الخلفية الموثوقة تحتاج خادمًا وهو مرفوض)، ترتيب (يدوي/تاريخ/أبجدي)، ألوان القوائم، سحب بين القوائم.
- **شرط:** قياس `liveQuery` وسحب dnd-kit على جهاز بطيء (CPU throttling) قبل رفع الحجم؛ ودمج `steps` ليس «الأحدث يفوز كاملًا» إن بدأ التكرار يغيّر شكل السجل.

### G — نسخ احتياطي مزامَن (بعد A0 وتثبيت دمج السجلات)

- منفذ `BackupProvider` ومحوّل Google Drive (`appDataFolder`) اختياري. بلا خادم.

### H — جودة وهندسة مستمرة

- وصولية (قارئ شاشة، تباين)، ميزانية أداء، انحدار بصري بلقطات CI، أرقام عربية اختيارية، i18n إن لزم، اختبار على جهاز أندرويد منخفض الإمكانات.

## 5. المراجعة والتحقق

- **وكيل مراجعة مستقل** (لم يرَ عملية البناء) يقرأ المستودع مقابل هذه الوثيقة وسياسة nawy-architecture، ويُصدر ملاحظات بملف وسطر؛ تُعالَج أو تُرفض بسبب مكتوب قبل مرحلة A. سجل ملاحظاته وقراراتنا في [`REVIEWS.md`](REVIEWS.md) (مراجعة 1 تمت وغيّرت الترتيب أعلاه).
- لا تُعلَن ميزة «جاهزة» بلا ذكر ما لم يُختبر (الجهاز الحقيقي، iOS، الإشعارات).
