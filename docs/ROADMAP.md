# خارطة التطوير — Nawy To Do (جوال أولًا)

الهدف: تطبيق مهام بمستوى Google Tasks وMicrosoft To Do، **يعمل كأنه تطبيق أندرويد أصلي** (لمس وإيماءات وتثبيت ومشاركة)، ويصلح للويب والديسكتوب، بكود معياري يُصان ويتوسع. ثقيل الشغل يؤجَّل ولا يُرتجَل: كل مرحلة صغيرة، تُنشر، وتُراجَع قبل التي بعدها.

## 1. أين نحن (لقطات الإنتاج من CI)

اللقطات تُلتقط آليًا من النسخة المبنية بشاشة Pixel 7 وديسكتوب، وتُنشر على الفرع [`ci-screenshots`](https://github.com/inawy/nawy-do/tree/ci-screenshots) (`android-1-main.png`، `android-2-details.png`، … و`chromium-*`). كل مرحلة تُقارن بها.

ما تراه فيها اليوم، بصراحة:

| ملاحظة                                                                     | الأثر على الجوال                                               |
| -------------------------------------------------------------------------- | -------------------------------------------------------------- |
| زر «تحديد» بلا تنسيق (زر المتصفح الافتراضي) وشريط عنوان مزدحم بثلاثة أزرار | يبدو غير مكتمل؛ يحتاج قائمة «المزيد»                           |
| خانة الإضافة أعلى الشاشة                                                   | بعيدة عن الإبهام؛ التطبيقات الأصلية تضعها أسفلًا (FAB أو شريط) |
| حقل التاريخ بصيغة `mm/dd/yyyy` الإنجليزية                                  | يكسر العربية؛ يحتاج منتقي تواريخ مُحلّى                        |
| لا إيماءات (سحب جانبي للإنجاز والحذف، ضغط مطوّل للتحديد)                   | غياب أهم عادات الجوال                                          |
| الورقة السفلية لا تُسحب للإغلاق                                            | تعوّد المستخدم على سحبها                                       |
| ديسكتوب: عمود ضيق وفراغ كبير                                               | يحتاج تخطيطًا أوسع ولوحة تفاصيل جانبية                         |
| CSS كتابة يدوية واحدة لكل شاشة                                             | يصعب توسيعه باتساق                                             |

## 2. المبادئ المعمارية (لا تُكسر)

1. **الطبقات** `core ← data ← features ← ui ← app` بقواعد ESLint (D-004، D-015). لا تجاوز.
2. **منافذ ومحوّلات (Ports & Adapters)**: ما يخص مزوّدًا خارجيًا (Dexie، Drive، إشعارات، مشاركة) خلف **واجهة** في `core`، ومحوّل واحد في `data/adapters`. الواجهة لا تعرف إلا الخدمات. _هذا غير مكتمل اليوم: `features` تستورد `NawyDoDb` مباشرة (المرحلة A)._
3. **كل موديول بواجهة عامة `index.ts` فقط**، بلا استيراد عميق.
4. **القلب نقي**: بلا React ولا DOM ولا ساعة (D-005).
5. **لا ملف يتجاوز ~200 سطرًا ولا دالة تتجاوز مسؤولية واحدة**؛ المكوّن الكبير يُقسَّم، لا يُتجاهل. (قاعدة لينت للحجم تُضاف في المرحلة A.)
6. **اعتماد جديد = سطر سبب في `DECISIONS.md`** وإصدار مثبّت (سياسة nawy-architecture). نفضّل الـ Web Platform على المكتبة.
7. **لا حذف فعلي**: tombstones والدمج على مستوى السجل (D-006). أي مخطط جديد = نسخة Dexie جديدة + نسخة أمان.
8. **الجوال أولًا في التصميم والاختبار**: كل ميزة تُصمَّم لشاشة 360px ولمس، ثم تتسع.

## 3. المكتبات المعتمدة (الستاك: TypeScript + Vite + React + Tailwind + ESLint)

حالة التحقق: **لم أستطع قراءة صفحات npm/GitHub من بيئة العمل** (غير مسموحة)، فأرقام الإصدارات تُثبَّت وتُتحقق في أول CI لكل مرحلة، ولا تُعتمد قبل أن يمر.

## 4. المراحل

كل مرحلة: PR أو أكثر صغير، بوابتها الإلزامية (tsc + lint + format + vitest + build + e2e)، **لقطات قبل/بعد**، ومراجعة معمارية مستقلة (§5) قبل الدمج للمراحل المعمارية.

### A — أساس معماري (قبل أي ميزة جديدة)

- منفذ `TaskRepository` و`ListRepository` في `core/ports`؛ محوّل Dexie في `data/adapters/dexie`؛ `features` تعتمد الواجهة فقط (D-024).
- قاعدة لينت لحجم الملف/الدالة، وفحص دوّارات الاستيراد.
- `package-lock.json` و`npm ci` وDependabot وحد حجم الحزمة (يحتاج منك رفع القفل).
- **قبول:** لا استيراد لـ Dexie خارج `data`؛ نفس الاختبارات تمر بمحوّل ذاكرة (دليل أن المنفذ حقيقي).

### B — نظام التصميم (Tailwind)

- إدخال Tailwind v4، تحويل `tokens.css` إلى `@theme`، وبناء `ui/primitives`: `Button`، `IconButton`، `Field`، `Sheet`، `Chip`.
- ترحيل موديولًا بعد موديول (shell، tasks، details، lists، backup) والتخلص من CSS اليدوي بالتدريج؛ لا «كل شيء مرة واحدة».
- **قبول:** لقطات مطابقة بصريًا قبل/بعد الترحيل؛ لا لون أو مسافة خارج الرموز.

### C — شاشة الجوال (شكل التطبيق الأصلي)

- شريط إضافة سفلي ثابت (أو FAB)، **قائمة «المزيد»** تجمع التحديد والبيانات والبحث، ترويسة تتقلص عند التمرير، مساحات آمنة (safe-area) وارتفاع `dvh`، أهداف لمس ≥ 48dp.
- منتقي تاريخ مُحلّى (اليوم/بكرة/الأسبوع القادم/تاريخ) بدل `mm/dd/yyyy`.
- **قبول:** لقطة Pixel 7 تُراجَع بصريًا؛ كل أداة بإبهام واحدة.

### D — الإيماءات

- سحب الصف: نحو الإنجاز (إنجاز) ونحو الجهة الأخرى (حذف مع تراجع)، **مع مراعاة RTL**؛ ضغط مطوّل لبدء التحديد (يحل محل زر «تحديد»)؛ سحب الورقة السفلية للإغلاق؛ اهتزاز خفيف (`navigator.vibrate` عند توفره).
- لا تعارض مع تمرير الصفحة ولا مع مقبض إعادة الترتيب (dnd-kit).
- **قبول:** اختبارات Playwright بإيماءة لمس حقيقية على مشروع `android`؛ ومعلن صراحة أن **جهازًا حقيقيًا لم يُجرَّب** حتى يجرّبه المالك.

### E — تكامل أندرويد (PWA متقدم)

- `manifest`: `shortcuts` (إضافة نية)، `share_target` (استقبال نص من «مشاركة»)، `display_override`، لقطات التثبيت، `theme_color` متكيف مع الوضع الداكن.
- شاشة تثبيت داخلية (`beforeinstallprompt`) واستعادة الحالة بعد إعادة التشغيل.
- **قبول:** فحص manifest آلي بالاختبارات؛ التثبيت الفعلي يتحقق منه المالك على هاتفه.

### F — ميزات المرتبة الأولى

- عرض «يومي» (النهارده)، تكرار المهام، وقت الاستحقاق، تذكيرات (أثناء فتح التطبيق؛ **الإشعارات الخلفية الموثوقة تحتاج خادمًا وهو مرفوض بسياسة المنتج**، فتوثَّق حدودها بدل الوعد)، ترتيب (يدوي/تاريخ/أبجدي)، ألوان القوائم، سحب بين القوائم.

### G — نسخ احتياطي مزامَن

- منفذ `BackupProvider` ومحوّل Google Drive (`appDataFolder`) اختياري، دمج السجلات الموجود يتكفل بالتعارض. بلا خادم.

### H — جودة وهندسة مستمرة

- تدقيق وصولية (قارئ شاشة، تباين)، ميزانية أداء (LCP، حجم JS)، اختبار انحدار بصري بلقطات CI، أرقام عربية اختيارية، ترجمة (i18n) إن لزم.

## 5. المراجعة والتحقق

- **وكيل مراجعة مستقل** (لم يرَ عملية البناء) يقرأ المستودع مقابل هذه الوثيقة وسياسة nawy-architecture، ويُصدر ملاحظات بملف وسطر؛ تُعالَج أو تُرفض بسبب مكتوب قبل مرحلة A. سجل ملاحظاته في `docs/REVIEWS.md`.
- لا تُعلَن ميزة «جاهزة» بلا ذكر ما لم يُختبر (الجهاز الحقيقي، iOS، الإشعارات).

## 6. المخاطر

| الخطر                                  | التخفيف                                                   |
| -------------------------------------- | --------------------------------------------------------- |
| تعذّر تشغيل npm محليًا                 | CI هو البوابة؛ تغييرات صغيرة وسريعة؛ إصدارات تُتحقق في CI |
| ترحيل Tailwind يكسر الشكل              | لقطات قبل/بعد وترحيل موديول بموديول                       |
| تعارض الإيماءات مع التمرير ومع dnd-kit | `touch-action` صريح، واختبارات لمس على `android`          |
| iOS مختلف عن أندرويد في PWA            | الهدف الأول أندرويد؛ iOS «يعمل بلا ضمان» حتى يُختبر       |
| تضخّم الحزمة                           | حد حجم في CI (المرحلة A)                                  |
